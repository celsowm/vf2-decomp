# P1 first step: 0x1680 contiguous 4B block stable across dual traces (v0730)

This note captures the **first factory-chain step** for P1
(`fa_player` corridor downstream of `0x28918`/`0x29414`):
running `frontier.contiguous_fighter_blocks()` on the existing
dual-trace player corpus and confirming the 0x1680 block is
stable across both traces.

The full P1 slice (downstream decomposition past `0x29414`) is
multi-hour ROM-backed work per the v0727 playbook and the v0730
first-action runbook; this commit documents the first bounded
factory-chain step so P1 has a clean pickup.

## Reproduction

```sh
python tools/python/_scratch_p1_block.py
# writes nothing to repo; out/p1-0x1680-block-stability.json is
# the JSON record (in out/, gitignored)
```

The `_scratch_p1_block.py` script is intentionally not committed;
the equivalent public API invocation is:

```python
from pathlib import Path
from frontier import Frontier

f = Frontier()
f.set_fighter_bases([0x510000, 0x520000], window=0x2000)
for trace in ["out/trace-both.jsonl", "out/trace-f0.jsonl"]:
    f.ingest_trace(Path(trace), trace)
for b in f.contiguous_fighter_blocks(
    width=4, min_count=2, min_length=120, ip_overlap=1.0
):
    print(b)
```

## Measured output (this run, on the existing corpus)

The detector surfaces exactly one contiguous fighter block from the
union of `out/trace-both.jsonl` (3,122 accesses) and
`out/trace-f0.jsonl` (3,075 accesses):

```
offset:       0x00001680
end_offset:   0x00001860
length:       120 offsets
byte_size:    480 bytes
width:        4
reads:        240
writes:       240
total:        480 accesses
base_count:   1   (only fighter0 = 0x510000, not dual-base yet)
top_ips:      [0x0002399c, 0x00023a38]
ip_overlap:   1.0
```

This **matches the v0729 evidence exactly** (see
`fa_player_struct_1680_corpus_v0729.md` and
`frontier_v2_player_corpus_v0729.md`). The block has been
re-discovered from scratch using only the public factory API — no
hand-enumeration.

## What this step proves

- The 0x1680..0x1860 block is **stable** across both
  `out/trace-both.jsonl` (which contains the dual-fighter render
  path) and `out/trace-f0.jsonl` (which contains a single-fighter
  alternate path). Same length, same IPs, same 1.0 IP overlap.
- The block is touched by exactly two guest IPs (`0x2399c` and
  `0x23a38`) — every offset in the block is touched by both IPs.
- The block is **not** currently dual-base (base_count=1): both
  traces only hit `fighter0 = 0x510000`, never `fighter1 =
  0x520000`. Per the v0729 evidence and the v0730 runbook, a
  fighter1-inclusive trace is required before the dual-base
  promotion contract fires.

## What the v0729 evidence locked in (still on master)

- The block is at the same offset in both traces (no fighter
  rebase between traces).
- The IP pair is the same: `0x2399c` and `0x23a38`.
- The reads/writes are balanced: 240 of each per 120 offsets
  (one read + one write per offset per IP).
- The block is **only** accessed by this IP pair — it is a
  per-frame dispatch boundary (a struct the dispatcher reads
  and writes each frame), not a per-call state machine.

## Dual-base promotion (not yet triggered)

The `infer_structs` dual-base contract (per
`tools/python/test_infer_structs.py::test_summarize_trace_dual_base`)
fires when the same offset is touched from both `fighter0` and
`fighter1`. The current dual-trace corpus does not exercise
fighter1; promotion requires a fighter1-inclusive trace.

Per the v0729 evidence the dual-trace corpus
(`out/trace-both.jsonl` + `out/trace-f0.jsonl`) was generated by
running the player chain in a state where only `fighter0` was
active. A new `out/trace-f1.vf2snap` (or similar) plus its
accompanying trace JSONL is the prerequisite for the dual-base
promotion contract to fire on the 0x1680 block. That capture is
out of scope for this commit.

## Anti-traps

- Do not promote `field_xxxx` to a semantic name (e.g. `health`,
  `animation_state`) without independent evidence.
- Do not commit `out/p1-0x1680-block-stability.json` — it lives
  in `out/` (gitignored) and is reproducible from the script.
- Do not hand-write the block detector's output; the
  `contiguous_fighter_blocks()` public API is the durable
  contract, with 18/18 unit tests pinning the behaviour.
- Do not weaken `infer_structs.py`'s conservative dual-base
  promotion; it requires actual evidence from both bases.
