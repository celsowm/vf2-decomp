# v0392 — player 0x142c0 geometry-expansion body: focused ROM-backed differential

## Boundary

`hybrid_execute_player_142c0` is the accepted native geometry-expansion
body `0x142c0 -> 0x14310` following the `0x1428c` head. v0391 recorded
the partial `resume-trace` witness (56 steps / +3 calls / +3 rets) but
left a focused ROM-backed fixture open. This version closes that gap.

## What changed

1. **New test-only entry** `vf2_hybrid_player_142c0_execute_for_test`
   (declared in `include/vf2/hybrid.h`, forwarded from the static
   `hybrid_execute_player_142c0` in `src/recovered/hybrid.c`), matching
   the existing `_for_test` wrapper pattern used by `0x19ef8`/`0x1428c`.

2. **New ROM-backed differential fixture**
   `tests/recovered/test_player_142c0_live.c`, wired into
   `CMakeLists.txt` as `vf2_player_142c0_live_tests` plus the
   `vf2_player_142c0_live_differential` ROM gate (mirrors
   `test_player_4505_live.c`). It restores `out/pre14288.vf2snap` into
   both machines, steps the reference interpreter through the full
   corridor + head + body to `0x14310` (10925 steps / +13 calls /
   +13 rets), drives the native wrappers through the same chain, and
   asserts exact step/call/ret lockstep plus full live-state equality at
   the `0x14310` boundary.

3. **Byte-exactness fix in the recovered body.** The focused fixture
   caught a register-modeling error that the coarser `native-sixth-
   dispatch` comparison (which runs far past this boundary to the
   scheduler, where `r15` is overwritten) did not expose. At the
   `0x14310` boundary the ROM leaves:

   - `r15 = phase` (byte at `0x0050002b`), from `ldob 0x0050002b, r15`
     at `0x142c4`;
   - `r14 = frame_phase` (byte at `0x00530005`), from
     `ldob 0x00530005, r14` at `0x142f4` (always 0 on the accepted
     `frame_phase == 0` path).

   The prior recovery wrote `registers[15] = g0` (g1==1) or
   `table_last_value` (g1==0), both of which are wrong for the live
   shape. Now:

   ```c
   cpu->registers[14u] = frame_phase;
   cpu->registers[15u] = phase;
   ```

## Witness (measured, current build)

From `out/pre14288.vf2snap` (parked at `0x14288`, `+0x1a4 == 0`,
`g0 == 0x505`):

- reference corridor `0x14288 -> 0x1428c`: 1622 steps / +4 / +4;
- reference head `0x1428c -> 0x142c0`: 9247 steps / +6 / +6
  (10869 total / +10 / +10);
- reference body `0x142c0 -> 0x14310`: 56 steps / +3 / +3
  (10925 total / +13 / +13).

At `0x14310` the reference register contract is now matched exactly by
the native body, including `r15 == phase == 0x11`, `r14 == 0`, and the
live pointer set (`g0` table pointer `0x020067bc`, `g19` scratch
`0x00520630`, `g20` command `0x00560000`, `g21`/`g22` cursors
`0x0050ea98`/`0x0050e2d0`).
